# 决策记录 0010：围串标条款不在本系统评审范围

- 日期：2026-11-09
- 状态：已采纳
- 关联：围串标功能下线（2026-11-05）、决策 0007/0008

## 背景

围串标（串通投标）分析由独立的围串标智能体负责。本系统已下线跨投标人串通信号与法规包中的串通条款（REJ-008/009/010），但**招标文件自身的评标细则**仍会编译出串通类否决条款。运行 85（PRJ-20261106-KDK2）剩余工作被这类条款主导：单条「串通投标情形认定」产生 1,337 个采集批次，且 V1 对横向条款按每个投标人重复采集全部 7 家材料（7 倍重复），是整场超时与 SQLite 写锁争用的主要来源。

## 决策

1. **本系统不评审、不评分、不否决围串标条款**。这些条款继续保留在冻结规则包中作为依据留档，但：
   - 不进入自动评审矩阵（不生成 `ScoreRecord`、不产生证据引文、不参与排名与总分）；
   - 报告与矩阵 API 增加 `out_of_scope` 清单，显式标注「围串标核查由独立智能体负责，本系统不评审（留空）」；
   - 不因这些条款缺评而阻塞报告或排名。
2. 判定采用确定性关键词规则（`backend/app/rules/scope.py`）：命中的是名称/描述/原文/证明材料中的明确串通语（串通投标、串标、围标、陪标、恶意串通、视为串通、同一 IP/MAC/CPU/硬盘、投标文件由同一单位或个人编制、投标保证金同一账户等）。普通资格、关联回避、业绩类条款不受影响；分类结果逐条留档，可审计。
3. 适用范围：**新发起的运行**（自动与历史人工路径均按同一规则过滤）。已有冻结运行保持原语义；运行 85 已按用户指令停止，不用本规则改写其历史结果。
4. 围串标相关代码/依赖（跨投标人共享采集等）保留作为通用能力，但不再因串通条款触发。

## 影响与验证

- KDK2 项目重新发起运行时，矩阵由 434 格降为 406 格，最重的串通认定条款不再产生采集批次。
- 判定模块有独立单测（`backend/tests/test_scope_policy.py`），实际冻结包 46 的命中清单为 c17/c32/c40/c41（均 veto），无误伤。
- 报告/矩阵的 `out_of_scope` 字段与前端「不在本系统评审范围（留空）」卡片为验收点。

## 不做什么

- 不伪造这些条款的结论，不写默认通过/否决，不把留空伪装成「已评审」。
- 不删除规则包中的条款原文（审计与交接给围串标智能体需要）。
