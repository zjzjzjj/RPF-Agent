# 决策记录 0007：全自动评审与严格完成条件

- 日期：2026-11-06
- 状态：已采纳
- 覆盖：0003 的后续人工兜底语义，以及 2026-11-04 资格审查弱化策略

系统自动完成全部应评条款。资格、符合性结论为符合、不符合或现有材料无法证实；不符合结论保留风险记录，投标人继续参与计分和排名。价格基准仍执行冻结细则中明确的纳入条件。

平台递交时间、现场密封等必须依赖外部记录的事实，缺少记录时可形成“现有材料无法证实”的最终风险结论。此结果不能用于掩盖 OCR、模型或引文核验故障。

关联关系、串通投标、报价横向比较等条款必须读取全部所选投标人的完整关联材料与冻结报价，每页保留所属投标人，按所有材料的最高数据分级调用模型。遗漏任何一家材料或原页读取故障均不能结项。文件内可比较的内容核查完成后，真实缺少平台 IP/MAC、银行流水或协商记录等外部事实时，才允许明确记录剩余证据边界。

已确认冻结总价作为程序输入使用，不能伪装成新的原文抽取事实。年度限价逐年抽取有证据的报价并由程序精确比较；总价低于合计限价不能证明年度报价合规。完整读取后确认缺少必需报价明细时按条款形成不符合，不能均摊总价、默认通过或以技术故障替代真实缺失。

初评未解决项最多再经过两轮定向补检、OCR 和按需视觉复核。视觉模型通过 `BID_EVAL_VISION_MODEL` 显式配置；端点和密钥可使用 `BID_EVAL_VISION_BASE_URL`、`BID_EVAL_VISION_API_KEY` 覆盖。需要视觉能力却未配置时明确失败。

PDF 的大幅嵌入图像即使与较长文字层共存，也必须经 OCR 或视觉核验。含图片的 DOCX 在无法可靠映射原始页图时明确失败，需提供保留分页的 PDF 并新建运行；不得用虚拟页或漏读的文字层伪装完整核验。

技术故障不得产生默认通过、最低档或零分替代评审结论。失败运行保留已完成项，并通过 `POST /runs/{run_id}/resume` 从断点继续；输入文件、报价或规则已变化时应新建运行。

初评及补评均不能以局部有效引文掩盖关联页读取失败。运行完成前在同一写事务重新验证冻结输入；跨进程执行通过操作系统锁互斥，重复领取任务不得覆盖原任务状态。

全部所选投标人与应评条款形成完整矩阵、最终分值合法、证据有效后，才发布正式报告和最终排名。失败或进行中的运行只展示已完成结果及进度。

价格引擎的自动路径使用 `compute_price_scores(..., strict=True)`。不完整公式、未完成门槛、无基准价、缺失离群参数和缺少逐产品报价输入的加权公式均明确失败，不得跳过规则或按总价近似。历史人工模式仍可读取，历史结果不会被批量改成自动完成。
