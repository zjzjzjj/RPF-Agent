# 自动评审执行器版本与上线约定

既有全自动运行继续使用执行器 V1。新建接口接受可选整数 `executor_version`，仅支持 1、2；缺省值由 `BID_EVAL_EXECUTOR_DEFAULT_VERSION` 指定，默认始终为 1，真实材料性能验收后才显式调整为 2。旧运行缺少该字段时固定按 1 解释，续评不得更换版本。`automation_version=1` 继续表示完整矩阵、最终结论和报告发布约束，与执行调度版本分开。

V2 使用独立提示词标识 `2026-11-06.auto-v2.2`。每个运行冻结提示词、模型、推理参数、文件原始哈希、解析页哈希、报价和规则。V1 续评不会因为无关的全局提示词标识升级而被阻断，执行时必须显式绑定原运行上下文；配置或实际输入发生变化时仍须新建运行。ContextVar 不会自动进入线程池，每个评分和采集 worker 应显式调用 `bind_run_execution`。

`review_collection_sets` 与 `review_collection_batches` 保存采集计划和批次检查点。采集完成不代表最终评分完成；原有完整矩阵判定、逐项评分事务及跨进程运行锁继续生效。查询接口的可选 `execution_progress` 单独展示材料批次和有效完成时间，不能把心跳、缓存命中或采集进度当作已评条款数。

V2 对横向比较条款先共享采集所有参评人的事实，再分别给每家投标人独立判断。事实必须保留所属投标人、原文件、页码、有效引文或页图哈希；同一事实的不同原始值全部保留。定向补抽仍无法消除的矛盾必须显示并阻止正式结论，不得挑选一个值制造分数。共享采集只减少重复读材料，不能共享某家投标人的最终分数。其他条款继续使用各自的评审链。

实际 HTTP 请求在宿主机共享 OS 槽位，总上限为 8；配置超过 8 仍受硬上限约束。PDF 文本、渲染与分类总并发上限为 2，OCR 并发上限为 2，等待期间不占数据库事务。排队、退避和缓存复用不扣 HTTP 调用预算；每次真实派发及重试各扣一次持久日预算，预算耗尽或取消须明确退出。各 worker 显式继承冻结执行身份与取消检查，不能在并发线程中退回当前全局模型配置。

采集计划将完整语义输入、模型身份、材料单元、批次顺序和验证器版本保存为不可变 `input_data`，签名同时绑定文字范围和实际页图载荷哈希。原页切片必须无遗漏、无重叠，空白页也必须唯一覆盖。每批结果核验后独立提交；后续批失败不得抹去此前结果。续评提升执行代次，只重做未完成或损坏的批次；旧代次的迟到成功与失败都不能覆盖新代次状态。OCR 或视觉补采须保存同运行、同条款、同文件页和同投标人归属的旧单元到新单元关系，所有读取故障解决后才可标记采集就绪。

综合判断在发送前按冻结上下文上限估算文本、结构开销与图像预算。超限时分组综合并逐级合并，保留完整且已验证的事实和来源；不得截断材料、用摘要抹去矛盾或直接用中间采集结果作最终评分。单个不可再分的单元仍超限时明确失败并保留已完成进度。

`GET /runs/{run_id}/execution-progress` 分别返回材料批次、唯一原页读取数、真实模型排队数、请求中数量、失败文件/页码/批次和最近有效完成时间。运行级请求观察器使用独立的 `execution-metrics` 记录，不能计入应读集合或完成矩阵；嵌套批次观察器不得重复计算实际 HTTP。终态运行的排队与请求中数量固定为零。最近有效进展取已完成批次或已自动确认评分的保存时间，心跳、排队事件和缓存命中不推进该时间。

上线验收使用同一批真实材料、冻结规则与模型，完成至少三组 V1/V2 配对的冷缓存、暖缓存运行，记录总耗时、实际 HTTP 次数、token、排队时间、模型耗时中位数和 P95、OCR/渲染时间、各条款结果和证据一致性。只有全自动完整矩阵、零故障兜底分、证据与结论验收均通过，并且代表性重条款的冷缓存耗时中位数较 V1 至少降低 30%，才能把新建默认切到 2。当前默认仍为 1；离线测试与请求次数下降不能作为已达到真实耗时提速百分比的证明。限制原页范围的诊断子集须明确标记，不能代替完整条款或整场矩阵验收。

生产环境（`BID_EVAL_ENV=production` 或设置静态资源目录的部署）启动只校验数据库结构。停发新任务、排空执行进程并保存完成项哈希后，显式运行：

```powershell
python scripts/migrate_execution_v2.py --database <bid_eval.db>
python scripts/migrate_execution_v2.py --database <bid_eval.db> --check
```

脚本使用 SQLite online backup，包含已提交的 WAL 数据；仅新增采集、预算计数及结构版本表。迁移幂等，不修改既有评分、引文和运行输入。开发测试仍可通过 `init_db` 初始化。回滚保留新增表与结果，使用识别版本并保留 V1 的兼容镜像；不得恢复旧数据库覆盖上线后的结果，也不得让未知 V2 运行落入历史执行器。

运行 85 默认等当前任务自然终态后升级。原实现把用户取消记为 `cancelled`，恢复只接受失败运行，不能以“取消再恢复”替代维护排空。部署后只对失败运行调用原恢复接口，保持完成项分数与引文不变。共享事实提示词等 V2 语义变更通过新运行验收。
